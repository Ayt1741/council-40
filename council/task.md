# ЗАДАЧА СОВЕТА (формулировка и факты; ход 57)

ПРОБЛЕМА. ИИ-агент заказчика (Arena Agent Mode: bash, файлы, веб-поиск; один диалог ≈1535 сообщений) снова и снова забывает и не выполняет «законы» заказчика (≈108 правил). В ходе 56 совет нашёл главный механизм: работу arXiv 2606.13174 «Recording-Compiling» — Trace (Test-time Rule Acquisition and Compiled Enforcement): правила пользователя компилируются в ПРОВЕРКИ, которые обязаны пройти ДО завершения задачи. Цифры статьи: память Mem0 оставляет 57,5 % нарушений; Trace снижает нарушения со 100 % до 37,6 % (в своей области) и до 2,0 % (вне области).

ФАКТЫ СРЕДЫ (не гипотезы):
1. У агента НЕТ платформенных хуков (нет PreToolUse/Stop, как в Claude Code). Есть: файлы рабочей папки, bash, панель действий с цепочкой хешей, проверка ответа перед отправкой (запускает сам агент), гейт (7 машинных проверок), журнал.
2. Trace требует HOOKS: verifiers прикрепляются к событиям prompt/tool-use/file-write/termination и БЛОКИРУЮТ событие при провале. В Arena таких событий нет — значит нужен эквивалент, который работает без платформы.
3. Заказчик не программист; вставляет одно сообщение в новый диалог; ценит простоту и «чтобы работало само».
4. Уже есть и НЕ помогло: журнал «читать первым», ядро-12 (печатать в начало хода), проверка ответа (10 проверок), гейт (7 проверок) — потому что все они ЗАПУСКАЮТСЯ САМИМ АГЕНТОМ, а не платформой.

ЧТО НАЙТИ: как построить «компиляцию правил в проверки» БЕЗ платформенных хуков — такой контур, где агент физически не может сказать «готово», не выполнив команду-проверку, и где обойти проверку дороже, чем выполнить. Нужны ГОТОВЫЕ проверенные людьми приёмы: make-подобные «обязательные цели», скрипты-«привратники» (git hooks, pre-commit), шаблоны ответа с обязательным полем-квитанцией, автотесты как условия завершения (spec-driven: tasks.md, RAPID, test-first agents), «Definition of Done» в агентных фреймворках, параллельные проверяющие агенты (LLM-as-judge с кодом), механизмы из Claude Code hooks / Codex / OpenHands / Aider / Cursor rules, из статей про runtime enforcement и «agent receipts». Каждый кандидат: ссылка + цитата + применимость в нашей среде (Python std-lib, файлы, bash).

ОГРАНИЧЕНИЯ: бесплатно; Python стандартной библиотеки; без хуков платформы; проверка детерминированная; агент сам решает, запускать ли проверку — значит нужна механика, где без запуска ответ неполон (не заполнено обязательное поле).
