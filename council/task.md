# ЗАДАЧА СОВЕТА (формулировка и факты; ход 55)

ПРОБЛЕМА. ИИ-агент заказчика (Arena Agent Mode: bash, файлы, веб-поиск; в одном диалоге ≈1535 сообщений, 78,8 млн знаков) снова и снова забывает и не выполняет «законы» заказчика (≈108 постоянных правил) и сказанное в сообщениях. Нужно найти ГОТОВОЕ, уже проверенное людьми решение (код, приём, инструмент, исследование), после которого проблема больше не возникает или возникает заметно реже и ловится сразу.

ФАКТЫ (из данных заказчика, не гипотезы):
1. Среда: контекст периодически СЖИМАЕТСЯ платформой в краткую сводку; внешних хуков нет (нельзя заставить платформу вставить правила перед ответом); системный промт менять нельзя; сессия может сама сменить модель при сбое (справка Arena). Живут только файлы рабочей папки и внешняя память (Telegram). Заказчик не программист; в новый диалог может вставить одно сообщение.
2. Постоянная память: файл законов (108 пунктов; номера 1–5 и 60–65 повторяются; 55 % пунктов содержат запрет/отрицание; есть противоречия, напр. «экономить токены» и «не меньше 100 запросов»), краткое ядро (~150 строк), журнал (2097 записей), Telegram-хранилище.
3. Уже сделано и НЕ помогло: журнал «читать первым» (скрипт печатает «100 % прочитано», в контекст ничего не попадает), гейт из 6 проверок (одна из них годами сравнивала число с константой), контракт из 16 пунктов, сверка ответов. Доля сообщений заказчика с руганью: 44 % в среднем; после защит 38–53 % (наблюдений мало).
4. Чем ругается заказчик: не выполняет законы; забывает сказанное; пишет «готово» без проверки; делает не то, что просили; выдумывает числа; не делает «100 запросов» (просили 29 раз, ≥100 поисков — 1 раз).
5. Связь с длиной хода: ходы ИИ длиннее (медиана 50 733 знака, до 1,7 млн) — ругани больше (34 % → 56 %); корреляция.
6. Ограничения решения: только бесплатное; Python стандартной библиотеки; без внешних хуков; без смены системного промта; проверка должна быть детерминированной, а не «ещё одной моделью, которая согласится».

ПРОТИВОРЕЧИЯ (для этапа 0, п.1): заказчик считает, что законы лежат в файлах и читаются каждый ход, а нарушения продолжаются, то есть чтение ≠ выполнение; заказчик хочет «никогда», а платформа не даёт принудительной проверки; больше правил в файле не равно лучше соблюдение.

ЧТО НАЙТИ: рабочий код/приём, воспроизведённый в issue, PR или открытом проекте; официальное подтверждение из документации; ≥2 независимых источника об одном и том же эффекте. Статья-обзор без кода и ссылок — не решение.
